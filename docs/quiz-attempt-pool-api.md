# Пул вопросов теста — что поменять на бэкенде

Клиент уже шлёт и читает новое поле. Пока бэкенд его не хранит и не проводит жеребьёвку сам, выборка на сдаче делается в браузере. Это временная схема: студент может увидеть весь пул в ответе `GET`. Ниже — как перенести жеребьёвку и оценку на сервер.

Сервис: **edu**, те же URL, что у тестов (`/api/v1/edu/`). Имена полей — camelCase, как у `timeLimit`, `maxPoints`, `showCorrectAnswers`.

## Смысл

Преподаватель собирает пул (например 50 вопросов) и задаёт, сколько вопросов студент должен получить (например 20).

При старте попытки сервер один раз случайно выбирает 20 вопросов из 50 и закрепляет их за этой попыткой. Повторное открытие теста возвращает тот же набор. Другой студент или новая попытка после сброса результата — новая выборка.

`maxPoints` и `minPoints` относятся к попытке (к тем 20 вопросам), а не к всему пулу.

Если `questionsPerAttempt` нет, равно 0 или не меньше размера пула — студент получает все вопросы. Старые тесты так и работают.

## Что сохранить на тесте

Новое поле теста:

| Поле | Тип | Правило |
|---|---|---|
| `questionsPerAttempt` | integer | от 1 до числа вопросов в пуле |

Принимать на `POST /testing/` и `PUT /testing/{id}/` и в JSON внутри `multipart` (`data`), и в обычном JSON. Отдавать в `GET /testing/{id}/` для автора теста вместе со всем пулом и правильными ответами.

Фронт шлёт его рядом с `timeLimit` и `maxPoints`:

```json
{
  "title": "Модуль 1",
  "timeLimit": 40,
  "maxPoints": 100,
  "minPoints": 60,
  "questionsPerAttempt": 20,
  "questions": []
}
```

## Попытка

Новая сущность **попытка** (`TestAttempt`), одна активная на пару студент + тест:

| Поле | Тип |
|---|---|
| `id` | uuid |
| `test_id` | uuid |
| `student_id` | int |
| `question_ids` | uuid[], порядок показа |
| `started_at` | datetime |
| `submitted_at` | datetime или null |
| `answers` | как сейчас |

Создавать попытку при первом заходе студента в открытый тест. `question_ids` — случайная выборка размера `questionsPerAttempt` без повторов (Fisher–Yates или `ORDER BY random() LIMIT n`). Сохранить порядок и больше не менять его до сдачи или сброса.

`POST /tests/{id}/reset-result/` удаляет попытку этого студента, чтобы следующая сдача получила новый набор.

## Что видит студент

`GET /testing/{id}/` для студента **не должен** отдавать весь пул и правильные ответы.

Отдать только вопросы попытки, в сохранённом порядке, и их id:

```json
{
  "id": "test-uuid",
  "title": "Модуль 1",
  "timeLimit": 40,
  "maxPoints": 100,
  "minPoints": 60,
  "questionsPerAttempt": 20,
  "attemptQuestionIds": ["q17", "q3", "q41"],
  "questions": []
}
```

`questions.length` равен `attemptQuestionIds.length`. В вопросах студента нет `is_correct` и `correctAnswer`.

Пока этого нет, фронт сам выбирает `questionsPerAttempt` штук из полного списка и запоминает id в `localStorage`. Как только `GET` вернёт `attemptQuestionIds` (или уже обрезанный `questions` длиной не больше лимита), браузерная жеребьёвка не используется.

## Сдача

`POST /tests/{id}/submit/`

Тело, как раньше, плюс id вопросов этой попытки:

```json
{
  "answers": [{ "questionId": "q17", "selectedOptions": ["opt-1"] }],
  "timeRemaining": 120,
  "showCorrectAnswers": false,
  "servedQuestionIds": ["q17", "q3", "q41"]
}
```

Оценивать только вопросы попытки.

- Не присланный вопрос из `servedQuestionIds` — пустой ответ.
- Ответ на вопрос вне попытки — игнорировать.
- `servedQuestionIds` сверять с сохранёнными `question_ids`. Если клиент прислал другой набор, брать серверный.
- Доля правильных считается от числа вопросов попытки: `score = round(maxPoints * correct / questionsPerAttempt)`.
- `passed = score >= minPoints`.
- Эссе по-прежнему `needsReview` и не входят в автомат, пока преподаватель не поставит балл.
- `totalQuestions` в ответе сдачи — размер попытки, не размер пула.

## Редактор преподавателя

`GET /testing/{id}/` для автора по-прежнему отдаёт весь пул, правильные ответы и `questionsPerAttempt`. Иначе редактор сохранит только выпавшие студенту вопросы.

Нельзя проводить жеребьёвку на этом ответе для автора.
